## Ce qu'on cherche (grille commune, CHARTE_UI)

1. **Structure d'écran** : titre + une phrase (périmètre et période) → au plus 2 actions visibles (`ActionBar` / `MoreActions` pour le reste) → filtres sur une ligne, repliables sous 640 px (`MobileCollapse`), puces retirables → 3 à 5 KPI → visuels → détail.
2. **Boutons** : verbe + objet, icône + texte pour les actions fréquentes, un seul primaire par zone, destructif = `ConfirmButton` avec conséquence, état en cours (`SubmitButton pendingLabel`), désactivé avec la raison, cible ≥ 40 px, boutons de formulaire en bas à droite (`FormActions`).
3. **Retours** : toast à chaque Server Action (`withActionToast` / `toastResult`), états vides `EmptyState` (quoi + pourquoi + action), squelette `loading.tsx` à la forme de la page, erreurs « ce qui s'est passé + comment corriger ».
4. **Navigation** : fil d'Ariane et retour contextuel (`Breadcrumb`, `safeReturn`), liens « Voir le détail » sur les KPI qui ont un drill-down, sommaire `OnThisPage` sur les pages longues, ligne de tableau cliquable (`rowHref`).
5. **Visuels** : titre = le message, sous-titre = mesure/unité/périmètre/période, axes nommés, valeurs sur les barres ≤ 12, « Voir les données », pas de débordement à 390 px. Passer par les helpers existants ; besoin dans `pbi.tsx` → demande dans CHANTIER_VISUELS.md (§ « Demandes hors périmètre »).
6. **Mobile et clavier** : rien ne déborde à 390 px (`min-w-0`, `overflow-x-auto` sur les tableaux larges ou `DataTable` en cartes), focus visible, ordre de tabulation logique, `aria-*` corrects.

Priorité : frictions de parcours (gravité 3-2) avant le cosmétique. Pas de refonte gratuite : chaque changement doit répondre à un point de la grille.
